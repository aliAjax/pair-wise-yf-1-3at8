# 救助站领养管理台

零依赖网页台（Python 标准库 + SQLite），解决三件事：

1. **同一只动物常被两人同时确认** —— 数据库唯一索引 + 事务兜底，同一动物只保留一份占名额的有效预约，两人同时确认只有一笔成功。
2. **到店体检异常挡不住已排好的领养** —— 确认时重新复核资格，异常或缺疫苗自动转「待复诊」，动物不能领走，补做并复核通过后才恢复。
3. **旧表数据与新记录冲突** —— 体检、疫苗、预约事件全部只追加（append-only），新记录永不覆盖旧记录；旧表导入有批次号防重复，导入的记录照常继续处理。

## 启动

```bash
python3 server.py
# 打开 http://127.0.0.1:8080
```

可选环境变量：`SHELTER_HOST`、`SHELTER_PORT`、`SHELTER_DB`。

- 首次启动自动建库 `shelter.db` 并写入演示数据（6 只动物、5 位领养人）。
- **重启不重建、不播种**，所有申请/候补/体检/复诊继续可用；删掉 `shelter.db` 才会回到初始状态。

## 业务规则

**开放领养（三条同时满足，任一不满足都在页面上显示具体阻塞原因）：**

- 隔离期已满（`quarantine_until` ≤ 今天）；
- 近 7 天内最近一次体检正常（无记录、记录过期、最近一次异常都算阻塞）；
- 疫苗齐全：猫需「猫三联 + 狂犬疫苗」，狗需「犬四联 + 狂犬疫苗」。

**预约状态机：**

| 状态 | 含义 |
|---|---|
| active | 唯一占名额的有效预约，可「确认领走」 |
| waiting | 候补，可多人，按登记时间排序，显示候补序号 |
| pending_recheck | 到店体检异常/缺疫苗，动物不能领走，占名额但不可确认 |
| completed | 复核通过、已领走（终态） |
| cancelled | 取消（终态） |

- 申请时动物不开放 → 直接拒绝并给出原因；已有 active/pending_recheck → 进入候补。
- active 取消或 completed 后，同事务内把**登记最早**的候补提升为 active。
- 确认时若最新复核不通过 → 转 pending_recheck 并写明阻塞原因；登记复诊可补录到店体检结果和补做疫苗，系统重新复核，通过则恢复 active（旧的异常体检记录仍保留）。
- 点「并发确认演示（两人同时）」可直接在页面验证并发：两个确认请求同时发出，只有一笔成功。
- 顶部「导入旧表」写入一批旧预约（含一份待复诊+异常体检）；同批次重复导入会被拒绝。

## 页面能做什么

- 动物档案：开放状态、阻塞原因、有效预约人、候补队列、全部体检/疫苗记录（旧表记录有「旧表」标记）；
- 申请领养、取消预约、确认领走、登记复诊（体检结果 + 补打疫苗多选）；
- 预约队列：状态徽标、候补第几位、待复诊阻塞原因；
- 操作流水：所有状态变更只追加展示，来源区分「页面 / 旧表」。

```
static/styles.css

```
